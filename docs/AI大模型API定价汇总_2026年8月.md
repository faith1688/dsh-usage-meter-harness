## 第一部分：通用计费公式说明

所有厂商的 tokens 计费均基于"每百万 tokens 单价"，核心符号约定：

| 符号 | 含义 |
|------|------|
| `T_in` | 输入 token 数（不含缓存命中部分，视厂商口径而定） |
| `T_out` | 输出 token 数 |
| `T_hit` | 缓存命中的输入 token 数 |
| `T_miss` | 缓存未命中的输入 token 数 |
| `T_write` | 首次写入缓存的 token 数 |
| `P_in` / `P_out` | 输入 / 输出单价（元或美元 / 1M tokens） |
| `P_hit` | 缓存命中单价 |

### 公式类型一：基础计费（无缓存）

```
费用 = (T_in ÷ 1,000,000) × P_in + (T_out ÷ 1,000,000) × P_out
```
适用：xAI Grok、Cohere、腾讯混元、百度文心、百川（部分）、昆仑万维等无缓存机制的模型。

### 公式类型二：缓存命中/未命中拆分型

```
费用 = (T_hit ÷ 1M) × P_hit + (T_miss ÷ 1M) × P_in + (T_out ÷ 1M) × P_out
其中 T_in = T_hit + T_miss
```
适用：DeepSeek、Kimi、智谱GLM、阶跃星辰、小米 MiMo、豆包（缓存命中价）。

### 公式类型三：缓存写入+命中型（Anthropic / MiniMax / Qwen显式缓存）

```
费用 = (T_in ÷ 1M) × P_in
     + (T_write ÷ 1M) × P_write      ← 首次写入缓存时收取（高于普通输入价）
     + (T_hit ÷ 1M) × P_hit           ← 后续命中缓存时收取（远低于普通输入价）
     + (T_out ÷ 1M) × P_out
```
- Anthropic 区分 5 分钟缓存（写入价 = 1.25×输入价）和 1 小时缓存（写入价 = 2×输入价），命中价 = 0.1×输入价
- Qwen 显式缓存：创建按标准输入价的 125% 计费，命中按 10% 计费
- MiniMax：缓存读取与缓存写入分开计价

### 公式类型四：上下文缓存存储型（Gemini）

```
费用 = (T_cached_read ÷ 1M) × P_cached_input          ← 使用缓存内容作为输入
     + 缓存存储量(1M tokens) × 存储小时数 × P_storage  ← 缓存内容按小时收存储费
     + (T_out ÷ 1M) × P_out
```
适用：Google Gemini 全系（如 Gemini 3.5 Flash 存储费 $1.00/1M tokens/小时）。

### 公式类型五：上下文长度阶梯定价型

```
先根据单次请求的输入 token 总量（上下文长度）确定所处档位，再按该档位单价计费：
费用 = (T_in ÷ 1M) × P_in[档位] + (T_out ÷ 1M) × P_out[档位]
```
适用：豆包 Seed 1.6 系列（0-32K / 32K-128K / 128K-256K 三档）、Qwen3-max / qwen3-coder 系列、百度 ernie-5.0、小米 MiMo、智谱 GLM-4.7/4.5-Air、Gemini Pro 系列（≤200K / >200K）。

### 公式类型六：输入输出合并计价型

```
费用 = ((T_in + T_out) ÷ 计费单位) × 单价
```
适用：讯飞星火（按"万 tokens"合并计价）、百川 Baichuan4/4-Turbo/4-Air（按"千 tokens"或"百万 tokens"合并计价）。

### 公式类型七：Batch 批量折扣型

```
Batch费用 = 标准费用 × 0.5
```
适用：OpenAI、Anthropic、Gemini、Mistral、Qwen（Batch 调用半价）。

### 公式类型八：峰谷分时定价型（DeepSeek，2026-08-17 起生效）

```
高峰费用 = T_hit/1M × P_hit峰 + T_miss/1M × P_in峰 + T_out/1M × P_out峰
闲时费用 = 高峰费用 × 0.5（三项单价统一减半）
高峰时段：北京时间 9:00-12:00、14:00-18:00；其余时段均为空闲（谷）时段
```
适用：DeepSeek V4 全系（v4-flash / v4-pro）。离线批处理、代码扫描、长时 Agent 等实时性要求不高的任务可移至闲时执行以减半成本。
