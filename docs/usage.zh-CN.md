# 使用指南（中文）

> 还没装？先看 [安装说明](installation.zh-CN.md)。改配置的入口汇总见本文「六、修改配置（入口汇总）」。

## 一、读数区（composer dock）

进入任意对话，输入框上方会出现一行计量器：

```
模型名 · 本次 ¥12.34 · 余额 ¥99.65 · 12 次  ▼
```

- **模型名**：当前会话实际使用的模型。
- **本次**：本会话累计费用（无内置价格时显示「无价格」）。
- **余额**：DeepSeek = 真实余额（官方 API 锚点 − 实时消费）；其他厂商 = 全局账本值。负值显示「透支」红色。悬停可看「更新于/计算于」时间与汇率信息。
- **请求数**：成功请求次数。

点击展开**详情卡**：

| 区域 | 内容 |
|---|---|
| 用量表 | 按该模型的计费方式渲染：每行 = 用量名称 / tokens / 单价 / 小计 |
| 缓存命中率 | 命中 tokens 占比 |
| 高峰/低谷 | DeepSeek 峰谷价自动生效；**每个请求按发起时刻的时段整体计费**（发起于 17:58 的请求即使 18:08 结束仍按高峰价；发起于 7:59 的请求跨过 8:00 仍按闲时价），详情卡顶部标签按当前时间显示（峰谷价未生效时也有提示） |
| 推理 tokens | 已含在输出内，单独标注 |
| 每轮费用 | 轮次号、起止时间、当轮模型、金额；按日期分组；0 tokens 且被中止显示「对话被停止」 |

## 二、设置面板（用户自定义设置）

点击「用户自定义设置 ▼」展开全部可编辑项：

### 行1：币种（**显示币种**）
决定**余额、用量表、每轮费用显示成什么币种**（CNY/USD）。切换时立即换算显示值并刷新最新汇率。保存后生效。

> 与「单价编辑区的币种」不同——那是**定价币种**（见行3）。

### 行2：账户余额 / 充值（仅非 DeepSeek）
- **账户余额**：直接编辑 = 覆盖该厂商/模型的账本余额。
- **充值**：正数加、负数减，保存后立即生效并广播到所有会话。
- DeepSeek 不显示此项（余额来自官方 API）。

### 行3：模型单价编辑

```
模型单价编辑（模型名 · 单位：每百万tokens ¥/$）
计费方式 [ 下拉：8 种计费方式 ]
币种     [ 下拉：CNY/USD ]          ← 该模型的「定价币种」
用量名称（可改）        单价（可改）
输入（缓存命中）        0.5
输入（缓存未命中）      5
...
[保存单价]  [重置价格]
```

#### 计费方式（8 种，选择后行结构 + 计算方式一起切换）

| # | 计费方式 | 行结构 | 说明 |
|---|---|---|---|
| 1 | 基础计费（输入+输出） | 2 行 | 无缓存，输入/输出分开 |
| 2 | 缓存命中/未命中 | 3 行 | 命中按缓存价（约 0.1×输入价） |
| 3 | 缓存写入+命中 | 4 行 | 首次写入约 1.25×，命中约 0.1× |
| 4 | 上下文缓存存储 ⚠️ | 3 行 | 存储费无法自动计量，仅计缓存读价 |
| 5 | 上下文长度分档 ⚠️ | 2 行 | 取基础档（≤200K/≤32K） |
| 6 | 输入+输出合并 | 1 行 | 讯飞/百川统一单价 |
| 7 | Batch 半价（×0.5） | 保持 | 整单 ×0.5（Batch 调用，需手动启用） |
| 8 | 峰谷分时定价 ⚠️DeepSeek | 3 行 | 输入即高峰价，闲时自动 ×0.5 |

- 打开模型时下拉**自动选中**该模型当前的计费方式。
- 无法完整计量的类型（4/5）在选项中带 ⚠️ 并在下方显示说明。

#### 币种（定价币种）
该模型**单价以什么币种计价**（默认 = 模型原生币种，如 DeepSeek=CNY、OpenAI=USD）。切换时：若目标 ≠ 模型原生币种，会先刷新最新汇率，再把已填单价换算到新币种。

> **关键概念**：定价币种决定「怎么计价」，显示币种决定「看到什么」。费用按定价币种计算，再用显示币种展示——两者互不影响。

#### 保存单价 / 重置价格
- **保存单价**：把行结构、单价、计费方式、定价币种持久化到 `usage-meter.json`（刷新后按新价计算）。
- **重置价格**：官方模型 → 恢复内置行结构+单价+计算方式+币种；自定义模型 → 恢复为该计费方式的默认结构+币种。

### 汇率行

当「显示币种 ≠ 模型定价币种」（需要换算）时，设置面板显示：

```
汇率：1 USD ≈ 7.2543 CNY · 更新于 19:47:29（USD → CNY 需换算）
```

切换币种即时刷新最新汇率；此后每 4 小时在对话开始时刷新。

## 三、余额机制

| 厂商 | 余额来源 |
|---|---|
| DeepSeek | 官方 `/user/balance` 锚点 − 锚点后累计消费（实时、一次减法、绝不重复扣） |
| 其他厂商 | **全局账本**：按绑定键存余额。官方模型共享 `p:<厂商>`；自定义模型独立 `m:<provider>/<model>`。每次用量增量只扣本次差值费用，文件为权威，广播到所有会话。默认 0、可负（透支红）。 |

## 四、单价覆盖与持久化

所有修改都写入 `~/.dsh/usage-meter.json`：

```jsonc
{
  "providers": { "*": { "currency": "CNY" }, "openai": { "currency": "USD" } },
  "priceOverrides": {
    "my-gateway/my-model": { "prices": { "inputPerM": 3, "outputPerM": 15 }, "rows": [...] }
  },
  "balances": { "p:openai": { "balance": 100, "currency": "USD" } }
}
```

- 未知厂商/自定义模型也能直接套任意计费方式模板（覆盖即定价）。
- 如需清理，删除对应 `priceOverrides` 键或点「重置价格」。

## 五、其他厂商说明（参考计费）

- 内置 136 模型价格（2026-08-16 快照）仅作**参考**；价格变动频繁，请以官方定价页为准。
- 未核实的价格（如讯飞现行价、mimo-v2-flash 调价后）在源码中有 ❓/⚠️ 注释，请人工核对。
- 远端价格源：可在配置中设 `priceSourceUrl` 指向 LiteLLM 格式的 `model_prices_and_context_window.json`。

## 六、修改配置（入口汇总）

改任何配置后都需：**重启 dsh web + 强刷浏览器**。

| 想改什么 | 在哪改 |
|---|---|
| **DeepSeek API Key** | ① 重跑 `node install.cjs --key 新Key`（推荐，自动更新）② 编辑 `cordis.patch.yml` 的 `deepseekApiKey` ③ 环境变量 `DEEPSEEK_API_KEY` |
| 显示币种 / 刷新间隔 | `cordis.patch.yml` 的 `currency` / `refreshIntervalMs`，或 `node install.cjs --currency USD --refresh 14400000` |
| 模型单价 / 计费方式 / 定价币种 | 本文「三」的设置面板（保存后写入 `~/.dsh/usage-meter.json`） |
| 非 DeepSeek 余额 / 充值 | 设置面板 → 账户余额 / 充值 |
| 远端价格源 | `cordis.patch.yml` 的 `priceSourceUrl` |

配置文件：`~/.dsh/profiles/<profile>/cordis.patch.yml`（Windows：`$HOME\.dsh\profiles\web\cordis.patch.yml`）
